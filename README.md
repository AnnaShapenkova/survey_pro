# Survey Research — библиотека решений для онлайн-анкет

Форк [desk-research-ai-public](https://github.com/vasilievyakov/desk-research-ai-public). Сохраняет принцип исходника: независимые процессы, PostgreSQL, Telegram-бот и веб-библиотека в одном Docker Compose для Coolify.

Ежедневно читает источники SurveyJS, LimeSurvey и Qualtrics, сохраняет публикации целиком, выделяет технические решения и готовит русский дайджест. Руководство `ES 4.1. Инструкция.pdf` используется отдельно для адаптации под EnjoySurvey 4.1.

## Поток данных

```text
sources.json → scheduler → collector → оригиналы /data + PostgreSQL
                                      ↓
                                    worker → решения, цитаты, исходный код
                                      ↓
                поиск ← библиотека → Telegram: дайджест /ask /adapt
```

- `scheduler` запускает сбор сразу после первого старта, далее раз в 86400 секунд. Последний запуск хранится в базе, рестарт не обнуляет расписание. Дополнительный cron в Coolify не нужен.
- `collector` читает релизы GitHub, теги версий, страницы документации, списки публикаций, RSS/Atom. Дополнительный поиск находит GitHub-репозитории и читает README. Произвольного поиска по всему интернету в v1 нет.
- `worker` извлекает задачу, решение, платформы, темы, ограничения, точные цитаты и примеры кода. Код источника должен совпадать с исходным фрагментом. Модель оценивает содержательную новизну относительно последних находок; это эвристика, не гарантия полноты.
- `bot` использует существующий токен, принимает команды, сохраняет загруженные файлы и отправляет дайджест. В этом же контейнере работает веб-библиотека на порту 8080.

## Развёртывание в Coolify

1. Поместите содержимое папки в свой Git-репозиторий. PDF должен остаться в корне репозитория, чтобы попасть в образ. Токены и `.env` в Git не добавляйте.
2. В Coolify создайте Application из этого репозитория, выберите **Docker Compose**, файл `/docker-compose.yml`, базовую директорию `/`.
3. Задайте переменные:

| Переменная | Значение |
|---|---|
| `SERVICE_USER_POSTGRES` | Имя пользователя PostgreSQL; Coolify может сгенерировать |
| `SERVICE_PASSWORD_POSTGRES` | Сильный пароль PostgreSQL из букв и цифр; Coolify может сгенерировать. При спецсимволах нужна URL-кодировка в DATABASE_URL |
| `OPENROUTER_API_KEY` | Ключ OpenRouter |
| `MODEL` | Доступный вашему аккаунту ID chat-модели OpenRouter с JSON-ответами |
| `EMBEDDING_MODEL` | Например `openai/text-embedding-3-small`; нужен для поиска по смыслу |
| `TELEGRAM_TOKEN` | Токен уже существующего бота |
| `TELEGRAM_ALLOWED_CHAT_IDS` | Разрешённые ID личных чатов через запятую |
| `MINI_APP_URL` | Публичный HTTPS-адрес сервиса bot, например `https://your-domain.example`; приложение добавит `/telegram` |
| `WEB_PASSWORD` | Пароль веб-библиотеки |
| `WEB_USER` | Логин библиотеки, по умолчанию `research` |

4. Остановите прежний процесс этого Telegram-бота перед запуском нового. Polling должен получать обновления одним экземпляром. Если старый бот использовал webhook, удалите его при переключении; приложение не удаляет его автоматически и сообщает о конфликте в логах.
5. Запустите Deploy. Контейнеры: `postgres`, `scheduler`, `worker`, `bot`. Для веб-страницы назначьте HTTPS-домен сервису `bot`, внутренний порт **8080**. Для Telegram polling публичный домен не требуется.
6. Напишите боту `/id`, добавьте полученный ID в `TELEGRAM_ALLOWED_CHAT_IDS`, перезапустите `bot`, затем отправьте `/start`. Других пользователей добавляйте таким же образом. До настройки списка доступна только команда `/id`.
7. Проверьте `/status` и логи сервисов. Откройте веб-домен с логином и паролем. `/health` проверяет доступность базы и не раскрывает содержимое библиотеки.

По умолчанию дайджест готовится после **09:00 Europe/Moscow**, когда завершён текущий сбор и анализ. Если обработка затянулась, ожидание ограничено двумя часами: поздние находки попадут в следующий выпуск. Пустые дайджесты не отправляются. В сутки создаётся один выпуск; неприсланные находки переносятся. На одном выпуске — до 30 находок; длинный выпуск Telegram получает несколькими сообщениями.

Доставки учитываются отдельно по подписчикам. При ошибке повторяется только неудачная доставка (до 10 попыток с интервалом 10 минут). Если соединение оборвалось после получения сообщения Telegram, повтор возможен: внешнее API не обеспечивает exactly-once отправку. `/stop` прекращает доставку подписчику.

Официальные инструкции: [Docker Compose в Coolify](https://coolify.io/docs/applications/builds/docker-compose), [OpenRouter embeddings](https://openrouter.ai/docs/api_reference/embeddings), [Telegram Bot API](https://core.telegram.org/bots/api).

## Команды бота

```text
/id
/start
/status
/feed
/search рандомизация блоков
/ask Чем отличаются способы валидации в найденных примерах?
/adapt Как показывать вопрос только при выборе определённого ответа?
/stop
```

Обычный текст обрабатывается как вопрос по библиотеке. PDF, TXT, MD, JSON, JS, PHP, CSS, XML/LSS, CSV и YAML можно отправить файлом (до 20 МБ). Они попадут в общую библиотеку как пользовательские материалы EnjoySurvey. DOCX в первой версии нужно сохранить в PDF. Код из файлов никогда не исполняется.

### Лента внутри Telegram

Задайте `MINI_APP_URL` в сервисе `bot` и выполните Redeploy. При запуске бот обновит кнопку меню **«Лента»** и добавит кнопку **«Открыть ленту»** к ответам и дайджестам для разрешённых пользователей. Команда `/feed` присылает новую кнопку. Адрес старой кнопки может сохраняться в уже отправленных сообщениях: после обновления используйте меню или новую кнопку от `/feed`.

Mini App открывается по `/telegram`. Сервер проверяет подпись Telegram `initData`, время запуска и ID пользователя из `TELEGRAM_ALLOWED_CHAT_IDS` при каждом запросе ленты, поиска и оригинала. Пароль веб-библиотеки внутри Telegram не требуется. Обычный вход через корневой адрес сайта сохраняет `WEB_USER` / `WEB_PASSWORD`. Без данных запуска Telegram страница `/telegram` не раскрывает материалы. Данные запуска не передаются через URL и не сохраняются в браузере. Через час потребуется закрыть и снова открыть ленту.

Официальная документация: [проверка данных Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

`/adapt` ищет решения в публикациях и релевантные страницы руководства EnjoySurvey. Возвращает ссылки на фрагменты, сохраняет результат с моделью и версией инструкции. При недостатке данных модель должна отказаться от кода. Любая адаптация явно обозначается как сгенерированная и **не проверенная выполнением**. Проверка цитат не доказывает корректность всех выводов или совместимость кода.

## Источники и ограничения поиска

Редактируйте `sources.json`, затем пересоберите приложение. Поддерживаются `page`, `listing` с CSS-селектором, `rss`, `github_releases`, `github_tags`, `github_search`. У каждого источника есть стабильный `key`, `platform`, `source_type` (`official` или `community`) и необязательный `active: false`.

Для подключения обсуждений добавьте их RSS, конкретную страницу или список страниц. Автоматический сбор GitHub issues/discussions в начальную конфигурацию не включён. Ошибки сайтов отражаются в `/status` и логах; динамические страницы и сайты с защитой от ботов могут требовать другого источника или ручной загрузки. RSS/списки скачивают публикацию, но не переходят по ссылкам внутри неё.

Для GitHub рекомендуется `GITHUB_TOKEN` с доступом к публичным репозиториям: без него действует низкий лимит запросов на IP, особенно заметный при повторных ручных запусках. При исчерпании лимита остальные источники продолжают собираться; ошибку можно увидеть в `/status`.

Бюджет прохода ограничивается `MAX_PER_SOURCE` (15) и `limit` источника. Проход заканчивается после проверки заданного набора кандидатов; семантическое доказательство «в интернете больше нет существенных сведений» не выполняется. Переводы и пересказы с другим содержимым могут храниться как самостоятельные документы, но оценка новизны должна исключать повторы из дайджеста.

## Хранение и повторный анализ

Все новые таблицы имеют префикс `kb_`; старые таблицы исходного проекта не удаляются и не мигрируются автоматически. Рекомендуется отдельная база для форка.

- `kb_documents`, `kb_document_versions`, `kb_versions`: адреса документов, ссылки на версии, текст и SHA-256. Один и тот же текст по разным URL хранится один раз; оба адреса сохраняются. Изменение документа создаёт новую версию.
- `kb_chunks`: фрагменты текста, номера страниц PDF, полнотекстовый индекс и embeddings с ID модели. История доступна в базе; поиск использует последнюю версию документа.
- `kb_findings`: анализ с цитатами, исходным кодом, оценкой новизны, моделью и версией инструкции. Несколько версий анализа могут сосуществовать.
- `kb_generated`: ответы и адаптации с использованными фрагментами.
- `kb_digests`, `kb_deliveries`: выпуски и доставка каждому подписчику.
- `kb_sources`, `kb_runs`, `kb_state`, `kb_subscribers`: конфигурация, журнал, состояние и подписки.

Оригиналы сохраняются в томе `library` (`/data/originals`), PostgreSQL — в `pgdata`. Резервируйте **оба тома вместе**. В веб-библиотеке оригинал скачивается как вложение без исполнения HTML.

Для повторного анализа после смены `MODEL` или `PROMPT_VERSION` используйте SQL из `db/queries.sql`. Старые результаты остаются в базе.

## Поиск и расходы

Поиск сочетает полнотекстовый индекс и мультиязычные embeddings. В первой версии векторы хранятся в PostgreSQL JSONB и сравниваются в Python; поиск по смыслу ограничен последними `SEMANTIC_SCAN_LIMIT=20000` фрагментами. Для значительно большей базы потребуется векторный индекс. Без `EMBEDDING_MODEL` или при ошибке API остаётся поиск по словам; это отображается в логах. Индексация идёт в фоне, поэтому поиск по смыслу становится полным не сразу.

PDF импортируется локально, но его фрагменты отправляются в OpenRouter для индексации и ответов. Аналогично обрабатываются загруженные анкеты и скрипты. Модель и embedding-модель используют оплачиваемый внешний API; лимиты аккаунта устанавливаются у провайдера.

Полный текст хранится независимо от анализа. Чтобы ограничить расходы, по умолчанию анализируются первые `ANALYSIS_MAX_CHUNKS=40` фрагментов (примерно 90 тысяч символов). При неполном анализе карточка содержит отметку; остальные фрагменты доступны поиску. Контекст модели должен вмещать этот объём. Изображения и сканированные PDF без текстового слоя не распознаются.

## Локальный запуск

Нужны Python 3.12+ и PostgreSQL 17. `.env` загружается автоматически.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполните .env, создайте базу PostgreSQL.
.venv\Scripts\python main.py check
.venv\Scripts\python main.py collector
.venv\Scripts\python main.py worker
# В другом терминале:
.venv\Scripts\python main.py bot
```

`python main.py web` запускает только веб-библиотеку без Telegram. `python main.py scheduler` включает периодический сбор. `python main.py import "путь.pdf" --platform EnjoySurvey --reference` импортирует дополнительную документацию; без `--reference` файл анализируется как материал. Руководство из корня автоматически импортируется при запуске worker.

Проверки: `pip install -r requirements-dev.txt`, затем `python -m pytest`. Тесты с PostgreSQL запускаются только с отдельным `TEST_DATABASE_URL` и очищают таблицы `kb_` **тестовой базы**; не указывайте production.

Форк подготовлен локально. Публикация в GitHub, подключение настоящего токена и развёртывание в Coolify выполняются отдельно с вашими настройками.
